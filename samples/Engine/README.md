# Engine: sample solution

A synthetic Visual Studio C++ solution that builds with any installed Visual Studio (2019 or later). It is the test bed of the extension: every project exists to exercise one behaviour.

| Solution folder | Project | Type | Exercises |
| --- | --- | --- | --- |
| (root) | `Game` | Application, console | default startup project; references `Render`, `Audio`, `Platform`, `Math`; `Game.vcxproj.user` sets `--windowed` and `GAME_MODE=sample` for x64; prints its args, working directory, `GAME_MODE` and `ENGINE_FLAVOR` |
| (root) | `Audio` | DynamicLibrary | dll with exports |
| `Core` | `Math` | StaticLibrary | fails with `C1189` when `ENGINE_BREAK_BUILD` is defined |
| `Core` | `Containers` | StaticLibrary | mostly headers |
| `Core` | `Platform` | StaticLibrary | define `ENGINE_FLAVOR` from the environment variable of the same name; imports `out/generated/deps.props` without a condition |
| `Graphics` | `Render` | DynamicLibrary | precompiled header; includes a header generated by `Shaders` (solution-level dependency) |
| `Graphics` | `Shaders` | Utility | custom build step writing `out/generated/shaders.h` |
| `Tools` | `Editor` | Application | second application |
| `Tools` | `AssetCooker` | Application, console | reads `assets.txt` from the working directory; writes `cooked.txt` there with its arguments and `COOK_MODE` (launch tests) |
| `Tools` | `Legacy` | StaticLibrary | mapped only in `Debug|Win32` |
| `Tools` | `Deps` | Utility | stands for a package manager project such as conan: building it writes `out/generated/deps.props`; listed last in the `.sln`; every other project references it through `Build/Common.props` (no `.vcxproj` names it), so one MSBuild run on the solution fails from a clean state (`MSB4019` in Platform) and the extension's build in waves does not |
| `Tests` | `MathTests` | Application, console | exits 1 on failure |
| (root) | `Missing` | listed, no file | "file not found"; mapped without `Build.0` so the solution still builds |

Solution configurations, in file order: `Debug|Win32`, `Debug|x64`, `Release|x64`, `Release|Win32`.

All projects import `$(SolutionDir)Build\Common.props` (C++20, shared include directory, `ENGINE_FLAVOR`, output under `out/`, a reference to `Deps`), use `$(DefaultPlatformToolset)` and Windows SDK `10.0`, so nothing in the files depends on one machine.

## Build from a terminal

```powershell
$vswhere = "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe"
$msbuild = & $vswhere -latest -requires Microsoft.Component.MSBuild -find 'MSBuild\**\Bin\MSBuild.exe' | Select-Object -First 1
& $msbuild samples\Engine\Engine.sln -m -nologo -p:Configuration=Release -p:Platform=x64
```

`Release|x64` prints one expected warning, `MSB4121` for `Legacy`, which has no mapping in that configuration.

To see a failing build: set `$env:CL = '/DENGINE_BREAK_BUILD'` before the build and `$env:CL = $null` after it.
